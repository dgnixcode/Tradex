# Trading desk UI and interaction safety — 9 October 2026

The authenticated workspace has a shared navy/slate design system with clearer visual hierarchy, consistent controls, keyboard focus indicators, tabular numeric alignment and less animated movement. The public pages and embedded exchange chart retain their own styling. Existing concurrent dispatch and backend security work from `security-trading-audit-2026-10-08.md` is preserved.

## Changes

- The authenticated desktop and mobile shell headers were removed at the user's request, along with the blinking Desk badge and density preference. Mobile navigation remains in the bottom bar and More menu; sign-out remains in the sidebar. Trading restrictions and risk checks remain enforced in ticket/position controls and on the server.
- Positions have clearer summary metrics, grouped cards, account tables, separated management/exit controls, and a visible-position risk strip for missing stop losses and liquidation buffers below 10%. Hidden positions are excluded unless shown. Group expansion controls support the keyboard.
- Orders distinguish filled, working, rejected, uncertain/review, and neutral outcomes. A group with zero failures but resting orders is no longer labelled fully filled. Order expansion controls support the keyboard.
- Accounts, account analytics, and the chart's positions drawer inherit the shared typography, surfaces, controls and numeric layout. The order ticket has a wider desktop editing area and a sticky review area showing direction, instrument, order type, leverage, margin currency, target scope and per-account sizing.
- The ticket creates a preview; final authorization remains on the confirmation page. Confirmation renders the saved server plan, rather than falling back to a possibly conflicting local draft. Its footer states the direction and account count. Skips require acknowledgement and expired previews remain blocked.
- Exit and management dialogs receive safe initial focus, trap Tab navigation, restore the opener, and block repeated Enter. Pending money actions block Escape, overlay dismissal and the close button. The protection editor mounts only when open, avoiding conditional hook execution.
- Market-exit selections survive live updates. Excluded accounts remain excluded, newly appearing accounts stay unselected, and disappeared positions are removed from the selection.
- Synchronous guards prevent same-event duplicate confirmation, quick exit and group add/reduce/close/protection/leverage dispatch. The group management dialog also remains busy during leverage changes. Server receipts and locks remain authoritative across tabs/processes.
- Individual and group additions previously rounded quantities to two/four decimals before sending. Explicit quantities now preserve up to 18 decimal places. Percentage sizing and estimated required margin use integer decimal arithmetic; quantities round down and estimated margin rounds up. Missing required FX/basis data and unsupported precision block addition instead of inventing a conversion. Exchange step/minimum/fresh-balance checks still occur on the server.
- The progress screen's retry candidates exclude unknown/review outcomes, consistent with the backend prohibition on blind resends.

## Terminal compactness and currency/navigation refinement

- Removed the ticket's “Build your trade” intro and redundant preview copy; the scope, currency, sizing, risk note and Review action remain.
- Terminal account rows show identity, P&L, quantity, margin and actionable risk by default. Details reveal entry, mark, liquidation and protection levels. USDT contract prices are labelled USDT even when collateral is INR.
- Account/group/coin search, expand/collapse, and account exit review were exercised. Search filters visible account rows but group actions still explicitly target the original full group count. No money action was confirmed. Switching between panels resets their shared scroll surface to the top.
- Both position views use shared grouping with INR first, then USDT; stable order within each currency avoids P&L-driven movement. INR/USDT totals remain separate and ordered. Amber INR and cyan USDT badges identify margin/P&L currency without reusing directional profit/loss colours. Each card has one currency badge; repeated currency section headings were removed. Groups start expanded in both views; users may collapse them explicitly.
- The desktop sidebar remains thin at 80px and adapts row height to the viewport; mobile uses a two-column More menu. Observed sidebar/nav scroll heights equal client heights at 1024×560. Mobile terminal tabs are static above the panel, replacing the floating controls that covered account actions. Bottom navigation has reserved space; the last account's actions were observed above it when scrolled to the end. No horizontal document overflow was observed on the mobile terminal.
- New order drafts, individual/group additions and partial exits default to Qty. Quantity fields start blank and require deliberate sizing. Existing saved order drafts preserve their explicitly selected modes/values. TP/SL defaults to Exact Price for new drafts and individual/group management, preserving existing trigger prices. Percent options remain available. Trailing protection now distinguishes the initial price gap from ROE steps; see roe-trailing-stop.md for semantics and rollout.
- Quantity partial exits use integer decimal arithmetic through 18 places for the request, remaining size and proportional margin estimate. Blank/invalid/full/oversized partial exits are blocked. Group Qty means the same quantity per account, with that scope labelled explicitly. Invalid quantity input is preserved and rejected rather than stripping signs/characters into a different amount. The server still enforces current quantities, increments and venue minimums.
- Mobile management modal sections no longer shrink away their tab controls. Default Qty and Price controls were inspected in both group and individual dialogs without confirming mutations. Blank addition states ask for a valid size rather than falsely reporting insufficient funds.
- Final frontend build and all 30 frontend tests passed. The existing bundle-size advisory remains.

## Balance refresh and terminal menu follow-up

- Order, Watch and Positions use consistent outlined SVG icons, aligned labels, keyboard focus and pressed states. The open-position count has its own badge. Mobile controls occupy equal-width static tabs above the panel; desktop reserves the rail's actual width to prevent clipping.
- Selecting/restoring a group or individual account now refreshes exchange balances, then awaits account/group totals reloading. The Default group uses its actual enabled membership across strategy groups. Manual refresh uses the same exchange-read path. Reads run concurrently in bounded batches of eight; old selection completions cannot clear the current selection's pending/error state. Pending refresh blocks Review; failure displays a stale-funds warning, while Review may retry the server freshness check.
- The planner refreshes its resolved active accounts before sizing, including implicit Default, fallback and retry-failed scopes. Any failed read prevents a preview token. Member allocation is reloaded after sync; newly added members are excluded from that preview, and a member reactivated without a refresh forces another preview.
- Complete wallet snapshots now atomically zero previously stored currencies omitted from a successful exchange read. This fixes old funds surviving when the mapper drops zero wallet rows. Snapshot errors roll back all changes. Account refresh checks tenant ownership before calling the exchange port.
- Validation: root TypeScript, production web build, 602 backend unit tests, 38 frontend tests, repository rules and backend lint passed. The new disposable-database balance check passed 50 assertions; onboarding passed 48; eight planning/auth/no-submit checks passed 2,296; seven execution/retry checks passed 133. Exchange balance ports were mocked; no live order or production database was used. Browser checks covered tab switching and desktop/mobile layout with invented account data. The preview intentionally rejects sync mutations and therefore shows a refresh failure rather than demonstrating live exchange balances. The pre-existing bundle-size advisory remains.

## Release considerations

Changes are local and have not been pushed or deployed. No live trades were used for this UI work. Rehearse the main desktop and mobile flows in staging before release: group/individual market and limit orders, expiry/skips, partial outcomes, selection refresh, add/reduce, leverage, protection and exit. Check keyboard navigation.

ROE trailing additionally requires migration 039 and compatible trailing workers before activating the new UI. Existing live trails retain their price basis until explicitly re-enabled. See [ROE trailing stops](roe-trailing-stop.md) for semantics, compatibility and validation.

The combined backend/frontend release still requires the configuration, migrations 035/036, compatible worker/signer deployment and reconciliation procedures documented in the security audit. Other work present in the shared checkout must be reviewed with its own release requirements. Concurrent request dispatch cannot guarantee simultaneous exchange fills or zero slippage, and this work does not certify an error-free or attack-proof trading system.
